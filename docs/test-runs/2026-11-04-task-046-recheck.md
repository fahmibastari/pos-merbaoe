## Perbaikan lingkungan pengujian

Enam kegagalan Sesi 40 tidak berulang pada PostgreSQL 16 lokal terpisah. I-03/I-05/I-06
sebelumnya timeout saat pembersihan fixture, kategori/login timeout saat membuka transaksi,
dan tes laporan membandingkan agregat global dengan fixture pada database demo.

- `scripts/test-environment.mjs` mewajibkan `TEST_DATABASE_URL`, memvalidasi nama database
  khusus `test`/`qa`, menolak database aplikasi `.env`, dan mengarahkan proses test ke QA.
- Tiga test pengaman mencakup target belum dipilih/invalid, target sama dengan aplikasi,
  dan pemisahan runtime/migrasi tanpa mengubah environment asal. URL invalid tidak
  mengungkap isi kredensial dalam error.
- `npm run qa:local` membuat PostgreSQL sementara, menerapkan migrasi/seed, menjalankan
  seluruh `npm run qa`, kemudian membersihkan instance miliknya. Docker adalah default;
  `QA_POSTGRES_MODULE` dapat menunjuk runtime portable di luar dependency aplikasi.
- Playwright selalu memulai server sendiri agar tidak memakai server development yang
  mungkin terhubung ke database aplikasi. Runner lokal memakai port aplikasi 3100.
- CI menyediakan `TEST_DATABASE_URL` menuju service PostgreSQL sementara yang sudah ada.

Docker Desktop di komputer ini gagal startup pada komponen secrets engine. Verifikasi
diselesaikan memakai PostgreSQL portable 16.15 di folder tooling sementara, tanpa
menambah dependency/lockfile aplikasi. Tidak ada migrasi, reset, seed, atau mutasi ke
Supabase pada sesi ini. `.env` aplikasi tidak diubah.

Percobaan portable pertama dihentikan sebelum QA selesai; folder datanya masih ada
karena pembersihan folder tersebut ditolak pemeriksaan otomatis (`blocked by policy`).
Folder itu terpisah dari database aplikasi dan tidak dipakai untuk hasil akhir di atas.
