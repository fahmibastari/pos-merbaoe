## Temuan

### QA-001 — F2 Tunai memfokuskan Diskon, bukan Uang Diterima · Medium · Ditutup 31 Agustus

- Reproduksi: tambah menu → metode Tunai → tekan F2.
- Aktual: active element adalah input `discountPreview`.
- Harapan: input `cashReceivedPreview` dipilih.
- Bukti source: `cashReceivedInputRef` terpasang pada input Diskon, sedangkan input Uang
  Diterima tidak mempunyai ref.
- Dampak: jalur keyboard kasir tidak menuju kontrol yang dijanjikan; pointer/Tab tetap
  dapat menyelesaikan transaksi.
- Perbaikan: `cashReceivedInputRef` dipindahkan dari input Diskon ke input Uang Diterima.
- Retest browser: tambah Americano → tekan F2; snapshot aksesibilitas menunjukkan
  `spinbutton "Uang Diterima (Rp)" [active]`. Keranjang uji kemudian dikosongkan.

### QA-002 — Pengumuman restore keranjang berpotensi dibaca dua kali · Low · Ditutup 31 Agustus

- Pesan “Keranjang sebelumnya dipulihkan” dikirim ke dua live region: `cartNotice`
  (`Feedback role=status`) dan `keyboardAnnouncement` (`p role=status`).
- Dampak: pengguna pembaca layar berpotensi mendengar notifikasi yang sama dua kali.
- Perbaikan: restore hanya mengisi `cartNotice`; live region keyboard tetap khusus
  interaksi keyboard yang tidak mempunyai umpan balik visual sendiri.
- Retest browser: tambah Americano → reload; snapshot aksesibilitas menemukan tepat satu
  kemunculan pesan restore. Keranjang uji kemudian dikosongkan.

### QA-003 — Logo shell dan foto menu pertama memicu warning LCP development · Low · Ditutup 31 Agustus

- Next.js berulang kali meminta `/Logo-Horizontal.png` dan foto menu di atas fold memakai
  eager loading.
- Dampak: tidak memblokir fungsi; perlu ditinjau pada performance polish dengan memberi
  prioritas hanya pada gambar yang benar-benar menjadi LCP.
- Perbaikan: seluruh logo di atas fold memakai `loading="eager"` sesuai kontrak Next.js
  16; prop `priority` yang deprecated dihapus. Foto menu yang terlihat di baris awal POS
  dan thumbnail pertama tabel juga dimuat eager, sedangkan foto selebihnya tetap lazy.
- Retest development: dashboard, halaman Menu, dan POS dimuat ulang setelah compile;
  tidak ada warning LCP baru pada output server.

### QA-004 — Instalasi `node_modules` semula mempunyai junction pnpm putus · High, dipulihkan lokal

- Fresh compile menemukan runtime `@prisma/client` dan `pg` tidak tersedia meski daftar
  paket lama melaporkannya terpasang.
- Instalasi lama dipindahkan keluar workspace; dependency direkonstruksi dari
  `pnpm-lock.yaml` dan `prisma generate` berhasil.
- Wrapper pnpm Codex masih menolak lifecycle build dengan `ERR_PNPM_IGNORED_BUILDS`.
  Dev/build dapat dijalankan langsung melalui binary Node/Next dan seluruh gate lulus.
- Dua salinan dependency lama yang dapat dipulihkan masih berada di folder sementara di
  luar workspace; source aplikasi dan lockfile tidak diubah.

### QA-005 — Tanggal pembelian/pengeluaran tampil mundur satu hari · Medium · Ditutup 31 Agustus

- Pembelian: input `2026-08-30`, baris riwayat menampilkan `29/8/2026`.
- Pengeluaran: input `2026-08-31`, baris riwayat menampilkan `30/8/2026`.
- Akar masalah: field Prisma `@db.Date` diparse dengan helper timestamp WIB. Nilai
  `00.00 WIB` menjadi `17.00Z` pada hari sebelumnya lalu PostgreSQL menyimpan bagian
  tanggal UTC yang salah; default tanggal pembelian juga memakai tanggal UTC browser.
- Perbaikan: field tanggal murni sekarang diparse/direntangkan pada tengah malam UTC,
  diformat eksplisit dengan zona UTC, sedangkan default form tetap memakai tanggal WIB.
  Expense otomatis dari waste juga mengikuti kontrak yang sama.
- Retest browser: pembelian dan pengeluaran fixture `2026-08-31` sama-sama tampil
  `31/8/2026` dan tetap ditemukan oleh filter `2026-08-31`–`2026-08-31`.
- Tiga regression test baru menjaga parse, format, rentang eksklusif, dan batas satu
  tahun untuk kolom `DATE`.

### QA-006 — Toggle kategori terlalu cepat membuat audit nonaktif ganda · Low · Ditutup 31 Agustus

- Saat aktivasi dipicu sekitar 900 ms setelah nonaktivasi, audit mencatat dua aksi
  `deactivate` sebelum satu `activate` berikutnya.
- Status akhir kategori tetap benar dan aksi biasa yang ditunggu sampai selesai lulus.
- Perbaikan berlapis: ref sinkron menahan panggilan UI kedua sebelum React sempat
  merender state pending; service di dalam row lock langsung mengembalikan hasil bila
  status target sudah tercapai sehingga update dan audit menjadi idempoten.
- Regression I-11 sekarang mengirim pasangan aktivasi/nonaktivasi paralel dan tetap
  mengharapkan tepat satu audit per transisi.
- Retest browser: dua klik Nonaktifkan bersamaan pada fixture kosong menghasilkan satu
  audit `deactivate`; fixture dan auditnya kemudian dihapus dan diverifikasi hilang.
